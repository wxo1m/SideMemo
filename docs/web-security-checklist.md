# SideMemo 웹 보안 검사 체크리스트

웹 클라이언트 전용 보안 검사다. 전체 제품의 데스크톱·공급망 검사는 `docs/security-review-checklist.md`에서 별도로 다룬다. 로컬 코드와 격리 브라우저를 우선 검사하고 운영 데이터는 읽거나 변경하지 않는다. 테스트 계정이 필요한 운영 정책 검증은 `미검증`으로 둔다. 결과는 `security-reviews/YYYY-MM-DD-web-review.md`에 기록한다.

- WEB-SEC-01 원격 HTML·붙여넣기 정화: script, 이벤트 속성, SVG/MathML, iframe/object, 위험 URL을 DOM에 허용하지 않고 기본 서식을 유지한다.
- WEB-SEC-02 첨부 이미지: 허용한 raster data URI만 렌더링하고 외부 URL·활성 콘텐츠를 거부한다.
- WEB-SEC-03 원격 payload: ID, 삭제 표시, 순서, 제목, HTML, 글꼴, 크기, 테마, 색, 첨부 형식과 크기를 검증하고 잘못된 데이터를 무시한다.
- WEB-SEC-04 계정 간 UI 격리: 로그아웃·세션 변경 뒤 이전 메모와 진행 중 응답이 화면·메모리에 남지 않는다.
- WEB-SEC-05 권한 정책: notes/settings에 RLS 소유자 정책이 있는지 로컬 SQL에서 확인하고 운영 정책은 별도 증거가 없으면 미검증으로 둔다.
- WEB-SEC-06 네트워크 정책: HTTPS 출처, CSP, referrer 정책, 고정된 외부 라이브러리 버전과 SRI를 확인한다. 호스팅 응답 헤더는 실제 공개 사이트에서만 판정한다.
- WEB-SEC-07 브라우저 저장소/로그: 토큰과 메모 저장 범위, 콘솔·오류 출력, URL 유출을 점검한다. XSS가 발생할 경우 세션에 미칠 영향도 기록한다.
- WEB-SEC-08 배포 상태: 검사한 소스와 공개 GitHub Pages 빌드가 일치하는지 구분하고 실제 공개 페이지 헤더·리디렉션은 접근해 확인한다.

항목 상태는 `통과 / 실패 / 미검증 / 해당 없음`을 사용한다. 로컬 테스트는 운영 DB RLS·실사용 계정·외부 브라우저 헤더가 통과했다는 근거가 될 수 없다. 보고서에는 영향과 남은 검증 조건을 함께 적는다.
